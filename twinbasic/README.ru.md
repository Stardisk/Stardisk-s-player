# Stardisk's Player — twinBASIC

[English](README.md) | **Русский**

Это старый плеер на VB6, преобразованный в проект twinBASIC и доработанный до актуальной версии. Основой стала версия без Windows Media Player из [legacy/vb6_nowmp](../legacy/vb6_nowmp/).

Legacy-версии VB6 были написаны без вайбкодинга. Эта версия twinBASIC частично разрабатывалась с его помощью. Основная версия C++ — этот плеер, переписанный на современный C++20 с помощью ИИ.

После переноса были доработаны воспроизведение, работа с файлами и потоками, управление с мультимедийных клавиш и интерфейс. Добавлена поддержка Unicode и подготовлена работа в x64. Основная идея осталась прежней: небольшой плеер, который играет файлы из выбранной папки без музыкальной библиотеки и лишних настроек.

Обычное воспроизведение использует системные DirectShow и Media Foundation. В коде есть подключение необязательной `reverse.dll`, но сама библиотека пока не включена в репозиторий. Без неё пункт реверса скрывается; обычное воспроизведение предусмотрено и без DLL.

## Что хранится в Git

- `source/` — распакованный проект: код, формы, встроенные ресурсы и настройки.
- `tools/impexp.mjs` — самостоятельный инструмент импорта и экспорта проектов twinBASIC, с исходным уведомлением MIT.
- `pack.ps1` — упаковка исходников в рабочий `.twinproj`.
- `export.ps1` — выгрузка сохранённого проекта обратно в `source/`.

Рабочий `.twinproj` и собранный EXE исключены из Git. Изменения кода и форм сравниваются по файлам в `source/`.

### Об инструментах импорта и экспорта

Скрипты в этом репозитории добавлены для удобства; это не встроенная интеграция с Git. Самостоятельный инструмент `impexp.mjs` описан в [документации twinBASIC](https://docs.twinbasic.com/Features/Packages/Import-Export-Tool). Он сам читает и записывает формат проекта, поэтому после обновления IDE совместимость может нарушиться. Официально поддерживаемый способ чтения и записи проектов вне IDE — через `twinBASIC_win32.exe` или `twinBASIC_win64.exe` из папки `bin` установленного twinBASIC.

`pack.ps1`, `export.ps1` и `tools/export-source.mjs` добавлены для этого репозитория. Они используют приложенный самостоятельный упаковщик и требуют Node.js. Для самого Git или GitHub эти скрипты не нужны.

Можно также открыть `source/` через **Import from folder** в IDE, а сохранённый проект выгружать через **File → Export Project**. Экспорт из IDE сначала очищает папку назначения: используйте отдельную папку для экспорта, а не корень репозитория или папку с рабочим `.twinproj`. Экспорт IDE может включать исходники пакетов компилятора; перед добавлением такой выгрузки в Git ознакомьтесь с документацией.

## Как открыть и собрать приложенными скриптами

Нужны Windows, twinBASIC с поддержкой Forms и Node.js 18 или новее. Node.js нужен только для упаковки и экспорта этими скриптами, для запуска плеера он не требуется.

Из корня репозитория:

```powershell
.\twinbasic\pack.ps1
```

Откройте `twinbasic/StardiskPlayer2NoWMP.twinproj` в IDE. Для текущей версии выберите цель **win64**: выбор архитектуры хранится в настройках IDE и не переносится вместе с проектом. Ссылки на пакеты twinBASIC и системные библиотеки перечислены в `source/Settings`; соответствующие зависимости должны быть доступны установленному компилятору.

Соберите проект в IDE. По настройкам проекта EXE создаётся рядом с `.twinproj`. Наличие twinBASIC не заменяет системные кодеки Windows: доступные форматы зависят от установленных компонентов.

## Как сохранять изменения

1. Отредактируйте проект в IDE и сохраните его (`Ctrl+S`).
2. Запустите из корня репозитория:

   ```powershell
   .\twinbasic\export.ps1
   git diff -- twinbasic/source
   ```

3. Проверьте изменения и сделайте коммит.

Экспорт сначала создаётся в пустой временной папке, затем обновляет `source/`, включая удаление файлов, которых больше нет в проекте. Не редактируйте `source/` параллельно с проектом в IDE: при экспорте она заменяется содержимым сохранённого `.twinproj`.

После `git pull` или переключения ветки закройте проект в IDE и заново упакуйте актуальные исходники:

```powershell
.\twinbasic\pack.ps1 -Force
```

`-Force` заменяет существующий рабочий `.twinproj`. Сначала экспортируйте нужные локальные изменения. Без этого параметра скрипт отказывается перезаписывать проект.
