# reverse.dll

[English](README.md) | **Русский**

`reverse.dll` — необязательная библиотека для активации функции реверса в Stardisk's Player. Версии C++ и twinBASIC загружают одну и ту же нативную x64 DLL из папки своего EXE. Для загрузки не нужны регистрация ActiveX/COM, установщик или права администратора.

Без DLL обычное воспроизведение продолжает работать, а пункт реверса скрыт. После добавления библиотеки перезапустите плеер: доступность проверяется при первом обращении к ней.

## Исходники и сборка

- `reverse.cpp` — экспортируемый API, сессии, рабочий поток и управление воспроизведением.
- `engine.h` — декодирование, индекс MP3, разворот PCM и вывод через waveOut.
- `api.h` — общие объявления C ABI и динамический загрузчик для C++.
- `build.ps1` — сборка x64 DLL с помощью LLVM-MinGW.
- `tests.cpp`, `test.ps1` — тесты API с генерируемым бесшумным WAV.

В Git хранятся только исходники и скрипты сборки/тестов. Готовые DLL/EXE, тестовое аудио, логи и промежуточные файлы исключены.

В Windows 10/11 x64 с установленным LLVM-MinGW запустите из корня репозитория:

```powershell
.\reverse\build.ps1
```

По умолчанию используется `C:\Program Files\LLVM-MinGW`. Другой путь задаётся через `-Toolchain 'C:\Tools\llvm-mingw'`. Результат — `reverse/reverse.dll`; скрипт не копирует её в другие папки.

Библиотека использует системные Media Foundation и waveOut. Стандартная библиотека C++ линкуется статически, поэтому сторонние DLL рантайма C++ рядом с ней не нужны.

## Как включить реверс

Соберите DLL и положите её рядом с EXE плеера. Для стандартных путей сборки в репозитории:

```powershell
# Плеер C++
Copy-Item .\reverse\reverse.dll .\cpp\reverse.dll

# Плеер twinBASIC после сборки его x64 EXE
Copy-Item .\reverse\reverse.dll .\twinbasic\reverse.dll
```

Если плеер собран в другую папку, скопируйте DLL туда. Перезапустите плеер, затем выберите реверс в меню «Режим» или нажмите ПКМ по Play в основном либо компактном окне.

При смене направления сохраняются позиция и пауза. Новые локальные треки в реверсе начинаются с конца. Повтор трека и фрагмента A–B учитывает направление. Реверс работает на x1 с заблокированной регулировкой скорости; при возврате к способу воспроизведения, поддерживающему скорость, прежнее значение восстанавливается. HTTP/HTTPS-потоки идут вперёд и не поддерживают реверс.

## API и ограничения

Версия интерфейса — `0x00010000`. Экспорты используют `WINAPI`, строки UTF-16 и непрозрачный указатель сессии (`LongPtr` в twinBASIC). Плеер C++ напрямую подключает `api.h` из этой папки. Перед закрытием сессии клиент должен прекратить обращения к ней.

| Экспорты с префиксом `Reverse_` | Назначение |
| --- | --- |
| `Version` | Версия интерфейса |
| `OpenW`, `Close` | Открытие локального файла и освобождение сессии |
| `Play`, `Pause`, `Stop` | Управление воспроизведением |
| `Seek`, `Volume` | Позиция в исходном файле в секундах; громкость сессии от 0 до 100 |
| `Duration`, `Position`, `State`, `Format` | Длительность, позиция, состояние, частота и число каналов |
| `ErrorW` | Текст ошибки в буфер клиента |
| `ExportW` | Явный экспорт PCM WAV для сравнений |

Способы `OpenW`: 0 — вперёд с полной распаковкой, 1 — полный реверс, 2 — блочный реверс. Плееры используют способ 2. Состояния: 0 — остановка, 1 — играет, 2 — пауза, 3 — конец, 4 — ошибка.

Декодирование и очередь звука работают в отдельном потоке. Исходная частота и число каналов сохраняются, отсчёты представлены в PCM16. Для MP3 библиотека хранит сжатый файл в памяти (до 1 ГиБ), индексирует кадры и декодирует участки с предшествующим контекстом; блочный способ не кэширует весь распакованный трек. Для других форматов Media Foundation используется поиск по временным меткам, точность которого зависит от системного источника. Моно и стерео проверены; многоканальная раскладка отдельно не проверялась.

## Тесты

```powershell
.\reverse\test.ps1
```

Скрипт собирает DLL и тесты, создаёт свой 30-секундный бесшумный WAV в `reverse/qa/` и проверяет API, обратный ход позиции, паузу, перемотку, громкость, стоп, конец трека, освобождение файла и запуск без DLL. Нужен LLVM-MinGW; путь можно задать тем же `-Toolchain`, что и при сборке. Node.js не требуется. Результаты тестов остаются в исключённых из Git папках `build/` и `qa/`. Системные аудиокомпоненты следует проверять в обычном сеансе Windows.

Для проверки интеграции с C++ скопируйте собранную DLL рядом с `cpp/stardisk.exe`, как показано выше, и запустите `cpp/test.ps1`. Скрипт тестов также помещает DLL рядом со своим тестовым EXE. Ранее выполненные проверки без DLL относятся к обычному автономному воспроизведению.

## Проверка этого переноса

DLL собрана из этих исходников. Прошли все 25 проверок API/отсутствия DLL, 119 проверок нативного воспроизведения и 90 проверок приложения C++ с установленной DLL. Интеграция проверялась на смене направления, сохранении паузы и позиции, скорости, повторе трека и A–B, потоках. Проект twinBASIC при этом переносе не пересобирался.
