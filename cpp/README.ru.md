# Stardisk's Player — C++

[English](README.md) | **Русский**

Это основная версия Stardisk's Player и база для будущих релизов. Она представляет собой версию twinBASIC, переписанную на современный C++20 с помощью ИИ и с использованием Windows API. Исходные версии VB6 были написаны без вайбкодинга; версия twinBASIC частично разрабатывалась с его помощью.

Идея осталась прежней: играть файлы из выбранной папки без музыкальной библиотеки. Поддерживаются Unicode в путях, компактный режим, операции с файлами, HTTP/HTTPS-потоки, мультимедийные клавиши, случайный порядок, повтор трека и фрагмента A–B, изменение скорости. В окне плеера стрелки влево и вправо перематывают на 10 секунд; в полях времени они сохраняют обычное перемещение курсора.

## Требования

Windows 10/11 x64. Для обычного воспроизведения достаточно собранного EXE; устанавливать Visual C++ Redistributable, .NET или Node.js для запуска не нужно. Используются системные DirectShow и Media Foundation, поэтому доступные форматы зависят от кодеков Windows. Интерфейс — на русском языке.

Плеер сохраняет `presets.ini` и `repeatlist.ini` рядом с EXE, поэтому папка должна быть доступна для записи. Реверс необязателен. Для его активации соберите необязательную DLL из [reverse/](../reverse/) и положите её рядом с EXE плеера. Без DLL пункт реверса скрыт.

## Состав исходников

- `src/` — исходники C++, Windows-ресурсы и значок программы.
- `src/ui.generated.h` — сохранённые в Git описания элементов и меню, сгенерированные из форм twinBASIC. Для сборки повторная генерация не нужна.
- `generate-ui.mjs` — повторно генерирует заголовок из `../twinbasic/source/Sources/`, без дублирующей справочной выгрузки.
- `../reverse/api.h` — общий интерфейс и загрузчик необязательной DLL. Реализация и инструкция сборки находятся в [reverse/](../reverse/).
- `tests/` и `test.ps1` — тесты воспроизведения и приложения, скрипты создания бесшумных WAV и локального HTTP-сервера.
- `build.ps1` — сборка x64 EXE и проверка импортов рантаймов.
- `tools/toolchain.json` — сведения о дистрибутиве LLVM-MinGW, использовавшемся при разработке. Сам компилятор в Git не хранится.

Результаты сборки, тестовое аудио, логи, личные настройки и справочные выгрузки исключены из Git. Готовые EXE и DLL не включены.

## Сборка

Установите LLVM-MinGW с инструментами для Windows x64. Из корня репозитория:

```powershell
.\cpp\build.ps1
```

По умолчанию компилятор ищется в `C:\Program Files\LLVM-MinGW`. Другой путь можно указать так:

```powershell
.\cpp\build.ps1 -Toolchain 'C:\Tools\llvm-mingw'
```

Результат — `cpp/stardisk.exe`. Промежуточные файлы, карта линковки и список импортов сохраняются в `cpp/build/`. Если плеер уже запущен, можно собрать файл с другим именем:

```powershell
.\cpp\build.ps1 -Output 'build\stardisk-check.exe'
```

Сборка использует `-nostdlib -nostartfiles -nodefaultlibs`, линкует импортные библиотеки Windows и отклоняет обнаруженные зависимости от CRT или стороннего рантайма. Node.js и twinBASIC для сборки плеера не нужны.

## Повторная генерация интерфейса

С установленным Node.js запустите из корня репозитория:

```powershell
node cpp/generate-ui.mjs
node cpp/generate-ui.mjs --check
```

Первая команда обновляет `src/ui.generated.h`, вторая только проверяет его соответствие формам twinBASIC и завершится ошибкой, если заголовок устарел. Изменения форм и сгенерированного заголовка следует проверять и коммитить вместе. Обычная сборка C++ использует готовый заголовок из Git.

## Тесты

Для тестов дополнительно нужен Node.js в `PATH`:

```powershell
.\cpp\test.ps1
```

Параметр `-WithoutReverse` проверяет обычное воспроизведение даже при наличии `cpp/reverse.dll`. При проверке без DLL скрипт удаляет её старую копию из `build/`, в том числе когда DLL рядом с плеером отсутствует. Если LLVM-MinGW установлен в другом месте, укажите `-Toolchain`. Тесты создают свои бесшумные WAV и настройки в `cpp/qa/`, запускают HTTP-сервер на `127.0.0.1:52751` и закрывают его после проверки. Тестовые EXE создаются в `cpp/build/`. Пользовательские музыка и настройки не используются.

Проверяются воспроизведение, громкость, скорость, перемотка, пауза, конец трека, освобождение файлов, HTTP, Unicode, INI и логика приложения. Без необязательной DLL также проверяется недоступность реверса.

Дополнительные проверки могут использовать локальный аудиофайл, открываемый только для чтения:

```powershell
.\cpp\test.ps1 -RateTestFile 'F:\Music\test.mp3'
.\cpp\test.ps1 -MediaTestFile 'F:\Music\test.mp3'
```

Для проверки скорости нужен файл длиной не менее 15 секунд. Файл для проверки Media Foundation должен задействовать этот резервный способ открытия. Некоторые системные мультимедийные тесты требуют обычного сеанса Windows вместо ограниченной песочницы.

## Релизы

Будущие релизы плеера собираются из `cpp/` в ветке `main` на выбранном коммите или теге. Готовые EXE размещаются в GitHub Releases, а не в исходниках. Существующий исторический релиз VB6 сохраняется.

## Проверка этого переноса

Копия с одними исходниками собирается LLVM-MinGW. Оба набора тестов — нативного воспроизведения и логики приложения — прошли в обычном сеансе Windows без `reverse.dll`. В ограниченной песочнице DirectShow и локальный HTTP работали некорректно, поэтому полный набор был повторно запущен вне неё.
